# z80

Fuse's Z80 core, lifted from `third_party/fuse-tspico/z80` (tag `tspico-v1.10.0-1`, `a43958d`), GPL-2.0-or-later. One of the two Phase 2 candidates (PLAN.md Phase 2): the other is ESPectrum's Z80_JLS. The choice is made by the P4 benchmark.

**Checked:** Fuse's own core tester (`test/z80`, `make -C test/z80 check`) passes all 1,356 tests in `tests.in`. That's every register, T-state and memory and port access, including contention. Both builds pass: `HAVE_ENOUGH_MEMORY` (prefixed opcodes inlined in one switch) and without it (one function per prefix).

## Files

| File | From | Changes |
|---|---|---|
| `z80.h` | `z80/z80.h` | Includes `libspectrum.h`; `z80_register_startup` removed |
| `z80_macros.h` | `z80/z80_macros.h` | Includes `z80_glue.h`. `IS_CMOS` is `Z80_IS_CMOS` (0, NMOS). The contention macros moved to `z80_glue.h` |
| `z80.c` | `z80/z80.c` | Fuse's headers replaced by `z80_glue.h`. Dropped: module and startup-manager registration, snapshot I/O, debugger variables, RZX frame handling, and the NMI paging for Scorpion, Beta and Spectranet. The interrupt test reads `z80_interrupt_length` and `z80_int_disabled` instead of `machine_current` and `scld_last_dec` |
| `z80_ops.c` | `z80/z80_ops.c` | The per-instruction hook list (`z80_checks.h`: profiler, RZX, automation, debugger, and the Beta, +D, DISCiPLE, Opus, Didaktik, IF1, DivIDE, DivMMC, uSource, uSpeech, Multiface, Spectranet and SVG traps) is gone, and with it the computed-goto setup. What's left: the fetch, the NMOS IFF2 check, and `EVEN_M1` dropped (not a TS2068 capability) |
| `opcodes_base.c`, `z80_cb.c`, `z80_ddfd.c`, `z80_ddfdcb.c`, `z80_ed.c` | generated by `z80/z80.pl` from `opcodes_*.dat` | None. Regenerate from `third_party/fuse-tspico` with `perl -Iperl z80/z80.pl z80/opcodes_base.dat > ../../z80/opcodes_base.c`, and the same for `cb`, `ddfd`, `ddfdcb` and `ed` |
| `z80_glue.h` | ours | Everything the core needs from outside: the clock, events, memory and I/O, contention, the /INT line, and the tape and SLT traps compiled out |

`compat/libspectrum.h` (ours) supplies the libspectrum integer types and allocation macros, in place of the generated real one.

## What the machine provides

From `z80_glue.h`:

- `tstates`, `event_next_event`, `event_register`, `event_add`
- `readbyte`, `readbyte_internal`, `writebyte`, `readport`, `writeport`
- `z80_interrupt_length`, `z80_int_disabled`
- a `z80_machine.h` with the `contend_read`, `contend_read_no_mreq` and `contend_write_no_mreq` macros (Fuse's: page contended → add `ula_contention[tstates]`, then add the time)

The per-access contention hook PLAN.md §3 requires is those three macros plus `readbyte`/`writebyte`. Only HOME RAM pages are contended (DOCK and EXROM never) because the machine says so, not the core.
